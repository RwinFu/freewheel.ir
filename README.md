# freewheel.ir

مرجع فنی فارسی و راست‌به‌چپ برای فری‌ویل و کلاچ یک‌طرفهٔ صنعتی. پروژهٔ Next.js در همین پوشه، سایت اصلی است و صفحهٔ اول آن از مسیر `/` ارائه می‌شود. تم روشن PR شمارهٔ ۵ در شاخهٔ `main` ادغام شده است.

## اجرا

نیازمندی‌ها: Node.js 22+ و npm.

```bash
npm ci
npm run dev
```

برای ساخت نسخهٔ production و اجرای آن:

```bash
npm run build
npm start -- -H 0.0.0.0 -p 3000
```

برای دیدن سایت روی دستگاه دیگر، آن دستگاه باید به سرور دسترسی شبکه داشته باشد؛ `localhost` فقط روی دستگاه خودتان کار می‌کند. لینک پیش‌نمایش محیط توسعه موقت است و جای استقرار پایدار روی دامنهٔ `freewheel.ir` را نمی‌گیرد.

بررسی کد:

```bash
npm run lint
npm run typecheck   # اول next typegen، بعد tsc --noEmit
npm run build
npm run verify      # فیلتر دسته‌بندی را در jsdom واقعاً اجرا می‌کند
```

`npm run verify` کامپوننت‌های فیلتر را با خودِ ری‌اکتی که App Router
باندل می‌کند رندر می‌کند، روی برچسب‌ها کلیک می‌کند و تعداد کارت‌های باقی‌مانده
را می‌شمارد. مرورگر لازم ندارد و در CI هم کار می‌کند.

> `next-env.d.ts` را پاک نکنید؛ همین فایل تایپ‌های ماژول‌های تصویر (`*.jpg`) و مسیرها را به TypeScript می‌دهد. اگر نبود، با `npm run typegen` دوباره ساخته می‌شود.

## فناوری‌ها

- Next.js App Router، React و TypeScript
- Tailwind CSS v4، GSAP/ScrollTrigger، Motion و Lenis
- View Transition API بومی مرورگر برای ترنزیشن صفحه‌ها
- فونت Vazirmatn به‌صورت محلی در `public/fonts/`
- تصاویر صفحات کاربرد از `src/assets/images/` (فایل محلی؛ بهینه‌سازی تصویر به میزبان بیرونی وابسته نیست)
- Drizzle ORM و PostgreSQL برای APIهای جستجو و ثبت درخواست

## موشن و ترنزیشن

ترنزیشن صفحه‌ها با View Transition API بومی مرورگر ساخته شده، نه با کتابخانه‌ی
انیمیشن؛ پس چیزی به باندل اضافه نمی‌شود و مرورگرهای بدون پشتیبانی، بدون خطا
به ناوبری عادی برمی‌گردند.

| الگو | کجا | چه چیزی را می‌رساند |
| --- | --- | --- |
| ترنزیشن جهت‌دار صفحه | همه‌ی صفحه‌ها | «رفتن به عمق» از چپ می‌آید، «برگشت» از راست (راست‌به‌چپ) |
| عنصر مشترک (morph) | `/applications` → صفحه‌ی هر کاربرد | همان تصویر است، نه یک تصویر دیگر |
| هویت آیتم فهرست | فیلتر دسته‌بندی | همان آیتم‌ها، چیدمان تازه |
| ریشه‌ی زنده | سراسر سایت | هدر چسبنده در میانه‌ی انیمیشن منجمد نمی‌شود |

نکته‌های پیاده‌سازی:

- جهت‌ها برای `dir="rtl"` تنظیم شده‌اند؛ در چیدمان راست‌به‌چپ، جلو رفتن یعنی
  حرکت به سمت چپ. آفست‌ها در `src/app/globals.css` هستند.
- نوع ترنزیشن روی خودِ لینک اعلام می‌شود: `transitionTypes={["nav-forward"]}`
  برای ورود به جزئیات و `["nav-back"]` برای breadcrumb. این پراپ از
  Next.js 16.2 در دسترس است.
- `src/app/template.tsx` حذف شد. آن فایل صفحه‌ها را در یک `motion.div`
  می‌پیچید و طبق قانون جای‌گذاری View Transition، همان پوشش باعث می‌شد
  `enter`/`exit` صفحه‌ها بی‌صدا از کار بیفتد.
- `src/types/react-canary.d.ts` تایپ‌های `ViewTransition` را فعال می‌کند؛
  `@types/react` آن‌ها را فقط در `react/canary` دارد و به‌صورت پیش‌فرض
  بارگذاری نمی‌کند.

همه‌ی انیمیشن‌ها به `prefers-reduced-motion` احترام می‌گذارند.

## دسته‌بندی محتوا

دسته‌بندی‌ها در `src/content/taxonomy.ts` و در یک جای واحد تعریف شده‌اند، پس
فهرست‌ها، صفحه‌های جزئیات و ناوبری از یک تعریف مشترک استفاده می‌کنند:

| صفحه | دسته‌ها |
| --- | --- |
| `/applications` | بک‌استاپ، حرکت پله‌ای، جداسازی و اورانینگ |
| `/ringspann` | پایه و داخلی، کامل و آماده‌ی نصب، کارکرد خاص |
| `/brands` | جایگزین آلمانی، سایر برندها |

اگر عضو تازه‌ای به محتوا اضافه شود و دسته‌اش تعریف نشود، `taxonomy.ts` در
زمان build خطا می‌دهد — نه پیش کاربر.

## داستان پروژه

بخش «داستان پروژه» در صفحه‌ی اصلی (`/#story`) از الگوی صفحه‌های کاتالوگ‌های
صنعتی آمده است: چند شماره روی قطعه‌ها و توضیح نقش هر قطعه — ولی بدون نقشه‌ی
خطی؛ هر شماره روی عکس واقعی خودِ قطعه می‌نشیند. دو فایل این بخش را می‌سازند:

| فایل | نقش |
| --- | --- |
| `src/content/story.ts` | همه‌ی متن‌ها: عنوان، عددهای پروژه، سه پرده‌ی روایت، وصله‌های شماره‌دار، نتیجه و درس‌ها |
| `src/components/story-parts.tsx` | شبکه‌ی کارت‌های عکس‌دار با شماره‌ی کورال و برچسب نقطه‌ی نصب |

نکته‌های محتوایی:

- روایت ترکیبی از پرونده‌های واقعی نوار نقاله است؛ نام کارخانه نیامده و عددها
  برای خوانایی گرد شده‌اند. اگر پرونده‌ی واقعی با اجازه‌ی مشتری اضافه شود،
  جای `PROJECT_STORY` همان است.
- عکس قطعه‌ها از `product-images.ts` می‌آید؛ یعنی همان آرشیو مشترکی که کارت‌های
  کاربردها، برندها و گالری صفحه‌ی اول از آن تغذیه می‌کنند. عکس تازه‌ای جدا
  نگه‌داری نمی‌شود.
- شش شماره، شش نقطه‌ی ممکن روی یک درایو نوار نقاله‌اند و همه به خانواده‌ای در
  همین سایت لینک می‌خورند (`fgr-r`، `bm-r`، `fkh`، `fz`، `frhn` و کاربرد
  نوار نقاله)؛ قطعه‌ای که در سایت پوشش ندارد به‌عنوان قطعه‌ی این سایت معرفی
  نمی‌شود.

از صفحه‌ی `/applications/conveyor` هم یک لینک متنی به همین بخش داده شده است.

## پایگاه داده

صفحه‌ها و جست‌وجوی کاتالوگ بدون دیتابیس هم کار می‌کنند: `/api/search` اگر `DATABASE_URL` تنظیم نباشد (یا دیتابیس جواب ندهد) همان کاتالوگ ایستای `src/content/ringspann.ts` را می‌گردد و نتیجهٔ یکسان با جدول‌های سایت می‌دهد. `/api/health` در این حالت `database: not-configured` و `search: catalog` می‌دهد.

فقط ثبت فرم‌ها به دیتابیس نیاز دارد. بدون آن، `/api/inquiry` عدد `503` با پیام فارسی و مسیر جایگزین (فروشگاه آنلاین) برمی‌گرداند و فرم همان را به کاربر نشان می‌دهد؛ هیچ درخواستی بی‌سروصدا گم نمی‌شود.

نمونهٔ متغیرها را در `.env.example` ببینید.

مسیرهای API:

- `GET /api/health`
- `GET /api/search?q=...`
- `POST /api/inquiry`

## انتشار عمومی

سایت کاملِ Next.js با APIهای جست‌وجو و ثبت درخواست روی میزبانی Node.js اجرا می‌شود. برای ثبت واقعی فرم‌ها، `DATABASE_URL` و PostgreSQL لازم است.

برای نمایش عمومی سایت روی GitHub Pages، یک **نسخهٔ نمایشی استاتیک** جدا بسازید:

```bash
npm run build:pages
```

خروجی در `pages-out/` است و با مسیر پایهٔ `/freewheel.ir` برای آدرس `https://rwinfu.github.io/freewheel.ir/` ساخته می‌شود. این دستور، APIهای سرور را فقط در پوشهٔ موقت ساخت کنار می‌گذارد و برنامهٔ اصلی را تغییر نمی‌دهد. جست‌وجوی کاتالوگ در نسخهٔ نمایشی داخل مرورگر انجام می‌شود؛ فرم درخواست در آن نمایش داده نمی‌شود و به‌جایش لینک فروشگاه و هشدار روشن وجود دارد تا اطلاعات کاربران گم نشود.

ورک‌فلو پس از هر push به `main`، نسخهٔ نمایشی را روی Pages منتشر می‌کند. برای انتشار دستی یک شاخهٔ بررسی‌شده، Workflow با نام «Validate and deploy site» را از تب Actions همان شاخه اجرا کنید. سبز شدن job ساخت (`build`) به‌تنهایی به معنی انتشار نیست؛ job انتشار (`deploy`) هم باید موفق شود. اگر اجرای `main` پیش از انتشار لغو شد، از تب Actions همین Workflow را دوباره با شاخهٔ `main` اجرا کنید. تا موفق شدن `deploy`، ممکن است آدرس Pages نسخهٔ قبلی را نشان دهد.

آدرس پیش‌فرض این GitHub Pages برابر `https://rwinfu.github.io/freewheel.ir/` است. برای استفاده از دامنهٔ سفارشی `freewheel.ir`، باید DNS و تنظیمات دامنهٔ میزبان جداگانه آماده شود.

## لایه‌های چرخان قطعه

بخش «اصل کار» صفحه‌ی اول روی **عکس واقعی** قطعه سوار است، نه نقاشی: یک عکس
استودیویی از روبه‌روی محور که به سه نوار هم‌مرکز بریده شده — حلقه‌ی داخلی،
قفس المان‌های قفل‌کننده و حلقه‌ی بیرونی. هر نوار در بوم مربعِ هم‌مرکز ذخیره
شده، پس `transform: rotate` روی هر فایل یعنی چرخاندن همان حلقه حول محور قطعه
(`src/components/axis-freewheel.tsx`). سرعت‌ها با مرحله عوض می‌شود: در چرخش
آزاد حلقه‌ی داخلی می‌گردد و قفس با نصف سرعت دنبالش می‌آید، در برگشت سرعت‌ها
به هم می‌رسند و در قفل هر سه یک‌پارچه می‌چرخند.

لایه‌ها با یک اسکریپت پایتونی از رندر خام ساخته می‌شوند (داخل وابستگی‌های
سایت نیست):

```bash
python3 -m venv .rendervenv && .rendervenv/bin/pip install numpy scipy pillow
.rendervenv/bin/python scripts/build_freewheel_layers.py --renders .renders
```

اسکریپت مرکز و شعاع بیرونی قطعه را با برازش دایره (RANSAC) روی لبه‌های تصویر
پیدا می‌کند، مرز نوارها را در همان شکاف‌های تیره‌ی بین حلقه‌ها می‌گذارد و یک
پس‌زمینه‌ی ثابت هم می‌سازد تا لبه‌ی نرم‌شده‌ی لایه‌ها روی خودِ عکس بیفتد و
درز دیده نشود. رندرهای خام در `.renders/` بمانند؛ در گیت نیستند.
